# 네이버페이 버튼 복원 (상품 상세) — 2026-10-23

zengenetics.co.kr(카페24) 상품 상세의 「장바구니 · 구매하기」 아래에 네이버페이 버튼을 되살리는 작업.
스킨 파일은 카페24 관리자(디자인 관리 → 파일 편집)에 있으므로, 이 폴더의 파일을 **그대로 옮겨 붙인다**.

## 왜 사라졌나 (라이브 소스 실측)

- 카페24 「네이버페이 구매」 앱은 마크업이 아니라 **런타임 스크립트**가 버튼을 만든다.
  `product_submit(2…)` 버튼을 찾아 그 부모에 `<div id="NaverChk…">` 를 붙이고, `nhn.CheckoutButton.apply()` 로 그린다.
- 2026-09-11 개편 때 `ds/js/detail-ui.js` 의 **R-12 블록**이 이 컨테이너를 `[id^="NaverChk"]` 로 잡아
  인라인 `display:none !important` 로 내렸다 (카카오페이·찜과 함께 제거하는 요건이었음).
  `product/detail.html` 에는 `<!-- 네이버페이·카카오페이 간편결제 — 2026-09-11 개편으로 제거 -->` 주석만 남아 있다.
- 되살렸을 때 정렬이 깨졌던 이유: 앱이 컨테이너에 `float:left; margin:20px auto 0; padding-right:10px; clear:both` 를 박고,
  위젯 자체가 285×88 고정(라벨 문구 + 구매/찜 버튼 + 이벤트 띠)이라 두 버튼 옆에 3번째 flex 아이템으로 끼어들었다.

## 배치

- PC: `.infoArea-footer .productAction .buy-btn-wrap` 을 `flex-wrap` 으로 두 줄 —
  1줄 장바구니·구매하기(기존), 2줄 네이버페이 **전폭 500×54, 모서리 13px, 간격 10px**.
- 모바일: 같은 노드가 구매 시트(`.mobile-layer.fixed.on`) 안에서 두 버튼(54px) 아래 **318×54** 로 붙는다.
  하단 고정바에는 넣지 않는다 (옵션을 고른 뒤에만 결제가 성립). `fitSheet()` 가 버튼 블록 높이를 실측하므로 합계 위치는 자동으로 올라간다.
- 네이버 공식 「N pay 구매」 버튼(스프라이트)을 그대로 쓰고, 라벨 문구·찜·이벤트 띠만 CSS 로 걷는다. 카카오페이는 계속 차단.

## 적용 순서

1. **`ds/css/detail.css`** 맨 끝에 `detail.css.append.css` 내용을 그대로 붙인다.
2. **`ds/js/detail-ui.js`** 를 이 폴더의 `detail-ui.js` 로 통째로 교체한다.
   (라이브 번들에서 복원한 원본에 R-12 블록만 바꾼 것. 바뀐 부분은 `detail-ui.js.diff`, 블록만 보려면 `detail-ui.js.R-12.replace.js`)
3. 스킨 HTML(`product/detail.html`)은 건드리지 않는다.
4. 카페24 관리자 → 앱 「네이버페이 구매」 설정은 현재 값(TYPE A · COLOR 1 · COUNT 2)을 유지해도 된다. 찜은 CSS 로 숨긴다.

## 지킨 규칙

- 스킨 파일 어디에도 네이버 컨테이너 id 전체 문자열을 쓰지 않는다 (A군 「플러그인 훅 보존」 검사 오탐 방지). `[id^="NaverChk"]` 접두사만 쓴다.
- detail.css 의 "새 `!important` 금지": moa 스킨의 `#…:not(:empty){width:49%}` 는 조상 `#contents` 를 붙여 특이도로 넘는다.
  네이버 위젯 내부(button2.css)는 전부 `!important` 라 같은 무게로만 덮을 수 있어, 이 블록의 `.npay_*` 규칙에 한해 예외로 허용했다.
- 앱이 만든 노드는 지우지 않는다 (지우면 앱이 `length == 0` 분기를 다시 돌아 무한 재생성). 숨기거나 인라인 스타일만 걷는다.
